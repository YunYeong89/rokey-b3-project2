모듈 관계

서버 상태는 PickupService 하나에 모여 있습니다. API 라우터와 로봇 연결은 이 객체만 받아서 씁니다. 모듈끼리 전역 변수를 주고받지 않습니다.

API 라우터 (pickup/api/)

각 파일에 build(svc) 함수가 있고, create_app(svc)가 이 함수들로 라우터를 모읍니다.

파일화면엔드포인트
shop.py손님 주문GET /api/products · POST /api/order · GET /api/status · POST /api/choice
recommend.py추천 · 고객 이력GET /api/recommend · /api/recommend/home · POST /api/rec_event · GET /api/rec_stats · /api/customer
staff.py직원GET /api/inventory · POST /api/scan · POST /api/restock · GET /api/pickups
pickup.pyQR 픽업GET /api/pickup/order/{id} · /api/pickup/qr/{id}.png · POST /api/pickup/verify · /api/pickup/manual
pages.py화면 · 데이터/ · /kiosk · /data/{path} (runtime/은 404)
schemas.py요청 본문 모델 (OrderReq, RestockReq, VerifyReq …)

주문 처리 흐름

  1. 손님 화면 → POST /api/order (shop.py): 주문을 저장하고(Orders.new) svc.robot.send_order() 호출
  2. 로봇(또는 Mock)이 /order_status를 보낼 때마다 svc.handle_status() 실행
    • need_choice → Recommender.substitute()로 대체 상품을 채움
    • done → 재고 차감, Orders.mark_ready()로 픽업 번호·token 발급, 구매 이력 저장
    • cancelled / error → 주문 상태 반영
  3. 손님 화면이 /api/pickup/order/{id}를 2초마다 확인 → 준비가 끝나면 QR 표시
  4. 키오스크 → /api/pickup/verify 또는 /manual → Orders.claim() → 로봇에 /pickup 발행
  5. 30분 안에 안 가져가면 Orders.sweep()이 expired로 바꾸고 직원 알림을 띄움 (R 계산에서도 빠짐)

실행

pip install fastapi uvicorn "qrcode[pil]"

python3 web_server.py --mock                        # 로봇 없이 시연
python3 web_server.py --mock --pickup-expire-min 1  # 픽업 만료 1분 (테스트)
python3 web_server.py                               # ROS2 환경: 터미널 1
python3 robot_order_node.py                         # ROS2 환경: 터미널 2

python3 -m pickup.history seed        # 샘플 고객 1234, 5678
python3 -m pickup.history show 5678   # 이력과 R 점수
python3 -m pickup.history events      # 추천 노출/클릭/구매 집계

모든 명령은 pickup_web/ 폴더에서 실행합니다. 손님 http://<PC IP>:8000/ · 직원 /#staff · 키오스크 http://localhost:8000/kiosk
